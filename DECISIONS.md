> [Phase 1] Build strategy — userspace must be built from **outside the repo tree** via `userspace/build.sh` using command-line `--config`, not `.cargo/config.toml` rustflags. Rationale: Cargo loads file config by CWD + ancestors, so building via `--manifest-path` from `/tmp` never loaded userspace's `.cargo/config` and `-no-pie` never reached `rust-lld`; meanwhile the repo-root `.cargo/config.toml` leaks the kernel linker script into any cargo invocation under it. Command-line `--config` always applies regardless of CWD (verified with a bogus-flag trick). Flags: `-Ttext=0x400000 -no-pie -e _start` → ET_EXEC @ 0x400000, entry 0x4000a0.

> [Phase 2] VGA device-buffer mapping belongs in `spawn_from_elf`, not per-server at boot. Rationale: the phase requires each freshly-spawned server's address space to contain its device buffer; centralizing the physical→virtual map (VGA_PHYS_ADDR 0xB8000 → VGA_BUFFER_VADDR 0x600000, flags PRESENT|WRITABLE|USER_ACCESS|CACHE_DISABLE) in `spawn_from_elf` guarantees every spawned process gets a coherent screen buffer and removes duplicated main.rs code. The old inline extern-C registry (`server_entry_point` + `cstr_eq`) was dead code (only referenced removed inline entry points, never called), so it was deleted rather than kept as "fallback" — the fallback is now the embedded-ELF path itself.

> [Phase 3] Activate IRQ routing by spawning the interrupt server at boot and calling `set_interrupt_server_pid(pid)` with its returned PID (the single missing wiring step; everything else — dispatcher, keyboard self-registration via MSG_IRQ_REGISTER type 6, build.rs embedding — was already present). Rationale: `forward_irq` routes through the ISR only when `INTERRUPT_SERVER_PID != 0`; previously it stayed 0 so IRQs used the legacy direct-delivery path and routing was never exercised. Chose to activate by default (Option A from the decision point), matching HITO-2's gate ("keyboard input works ... through the interrupt server"). Guarded with `if let Some(isr_pid)` so a failed spawn leaves PID==0 and keeps the direct-delivery fallback — a broken ISR must never break keyboard input. ISR spawned before the keyboard so it is up when the keyboard self-registers; `set_ready` (not running) matches the keyboard pattern since round-robin scheduling services it once IRQs are enabled after timer setup.

> [Phase 3 correction] Wire up `grant()` to fix dead capability-based IPC (Option 1 from REVIEW.md, resolving both 🔴 Critical issues). Rationale: with routing ON, every generic `ipc_send` hits `check_ipc_send`, but no process ever had a capability granted (`capabilities == 0`), so the keyboard's self-registration to the ISR (dst PID2 → KEYBOARD_SEND) and the ISR→keyboard hop (dst PID3 → DRIVER_SEND) were both rejected with -1 — keyboard input was completely dead. Chose baseline grant at process creation (`Process::new` → new `grant_initial_caps()` granting VGA_SEND/KEYBOARD_SEND/INTERRUPT_SEND/DRIVER_SEND) rather than per-server/per-role grants, because the spawn order (VGA=1, ISR=2, keyboard=3) makes hardcoded PID→cap mapping fragile and the reviewer already flagged that fragility; granting a uniform baseline is exactly what capability.rs documents ("granted at process creation"), fixes every legitimate IPC flow in one place, and cannot break existing behavior since it only makes `check_ipc_send` more permissive. FORK/EXEC intentionally left ungranted (gate privileged ops). Verified: clean `./build.sh` (no new warnings); confirmed both `check_ipc_send` callers (sys_ipc_send:331, sys_cap_send:660) and that fork/exec don't call it. Open minor items left for later (out of scope): asymmetric VGA bypass (#2), silent -1 rejection w/o EACCES diagnostic (#3), PID→cap fragility / per-endpoint table (#4), doc's nonexistent SYS_GRANT_CAP reference (#5).

> [Phase 4] Signal-wait blocking: reuse existing `ProcessState::Blocked` + a new per-process `deadline: u64` field (kernel ticks) instead of adding a new state variant; disambiguate signal-wait from I/O-block by requiring non-zero deadline. Rationale: phase constrains "keep signal definitions/state unchanged"; the `deadline` field alone distinguishes a real waiter (non-zero) from an I/O-blocked process (deadline==0), so `send_signal`'s existing `state==Blocked → READY` wake and the new timer `check_deadlines()` both work without touching the enum. Deadlines computed via `signal_state::compute_deadline(now, timeout)`; wakeup predicate is `ProcessState::Blocked && signal_state::deadline_expired(deadline, now)`. Pure logic lives in a standalone workspace crate `signal_state/` (core-only, host-testable AND bare-metal-compatible) so it can be unit-tested on the host without dragging in the no_std kernel bin's generated `server_images` module / paging/tss/vga; kernel calls it via `[dependencies] signal_state = { path = "../signal_state" }`. Verified: `cargo test -p signal_state --target x86_64-unknown-linux-gnu` → 4 passed; bare-metal `cargo +nightly build -Z build-std=core,compiler_builtins --target x86_64-unknown-none --release --bin kernel` → clean (no errors). Note: full end-to-end wake requires Phase 5's stack delivery; this phase covers block/wakeup logic only.

> [Phase 6] Storage path — fallback **kernel-side virtio-blk + BLOCK_READ/BLOCK_WRITE syscalls**, NOT MMIO-into-user-space. Rationale (the decisive constraint): QEMU `virt` defaults to the **SeaBIOS** firmware, which presents virtio-blk as a **legacy 0.95 PCI device**. Legacy virtio-pci exposes its config/queue region on **BAR0 as an I/O region** (accessed with x86 `in`/`out` port instructions), not as a memory-mapped MMIO window. An I/O-space region cannot be mapped into user address space via `paging::map_phys_page` (that maps physical *memory* pages only, see `VGA_PHYS_ADDR 0xB8000 → VGA_BUFFER_VADDR 0x600000`), so the VGA-style "kernel maps device MMIO into each server's page table" pattern is not achievable for a SeaBIOS legacy virtio-blk. Achieving true user-space MMIO would require **OVMF/UEFI** firmware presenting virtio 1.0 "modern" (BAR2 MMIO), which changes the boot handoff contract and cannot be tested here (no QEMU / no sudo). The phase's design directive explicitly sanctions this fallback: "if SeaBIOS only offers a kernel-consumable device, use a minimal block read/write syscall that userspace driver calls." Implementation: add PCI enumeration + a **minimal virtio-blk 0.95 legacy queue driver in the kernel** (`kernel/src/block_dev.rs`, replacing/augmenting the RAM disk) that performs raw 512-byte block transfer; expose `BLOCK_READ` (nr 24) and `BLOCK_WRITE` (nr 25) syscalls. All filesystem semantics (FAT16 BPB parse, root-dir listing, file read) live in **user-space crates** (`block_driver/`, `fs/`) that call those syscalls — so the *filesystem* runs entirely in user space; only raw block I/O crosses into kernel. Note this relaxes completion criterion 3 ("kernel only performs device mapping") to "kernel does raw block transfer via virtio; filesystem logic is in user space" — documented as an unavoidable consequence of SeaBIOS legacy transport. If/when the firmware is switched to OVMF modern, replace the kernel driver with a user-space MMIO virtio driver and drop the syscalls.

> [Phase 6 bugfix 2026-09-25] Correctness pass over the storage stack + host-test wiring (code verified, QEMU gate still pending). (a) PCI: `out dx,eax` with spec bit layout (enable<<31, bus<<16, dev<<11, func<<8, dword-aligned offset); vendor=low half / device=high half of config dword 0x00 (was comparing low half to the device ID — never matched). (b) virtio transport rewritten to the true legacy 0.9.5 I/O map (QUEUE_PFN@0x08, QUEUE_NUM@0x0C, QUEUE_SEL@0x0E, NOTIFY@0x10, STATUS@0x12, config@0x14, u64 capacity) with ACK→DRIVER→FEATURES_OK→DRIVER_OK handshake; queue = 2 verified-contiguous frames (desc+avail+req+status+bounce | 4K-aligned used ring); DMA via bounce buffer (never a virtual stack address); completion = used.idx CHANGE + status==0 (never instant-true on a zeroed page); contiguous/low-memory verified or RAM-disk fallback. (c) `read_bytes` underflow guard (`saturating_add` + `end<=offset`). (d) `BLOCK_READ/WRITE`: clamp to the 4096 staging buffer BEFORE validating, full-range `is_valid_user_range` (checked_add), read-modify-write for partial edge blocks (was zeroing neighbours) — full-block fast path skips the read. (e) FAT16: `root_dir_sector` no longer double-counts its own sectors; dir-entry cluster from 0x1A/size from 0x1C; `read_file` honours `min(out.len(), size)`; test fixture `make_image` now encodes the spec (multi-cluster chains, total-sectors u32 @0x20) + 3 new tests pinning absolute layout, chaining and clamping. (f) `signal_state::compute_deadline` saturating (overflow test fixed: MAX-5+2 never overflowed — new cases use MAX,1 / MAX-5,10). (g) Freestanding items (`_start`, boot.S, panic handler, `no_main`) gated on `all(not(test), target_os="none")` — `not(test)` alone still collides with libc on hosted builds; canonical host commands: `cargo test -p signal_state/kernel --target x86_64-unknown-linux-gnu`, `cargo test --lib` from `userspace/` (lib is `cfg_attr(not(test), no_std)`). (h) Deleted `kernel/tests/*.rs` (stale: referenced a `kernel` lib target and removed APIs — could never compile for a bin crate; unit tests live in `src/`). (i) `.gitignore`: `plan.md`, `PLAN.MD`, `phases/` are local agent noise. Verified: bare-metal `cargo check` + `./build.sh` release PVH clean; host kernel 7 passed / userspace 5 passed / signal_state 4 passed. HITO-4 still needs a real QEMU `-device virtio-blk-pci` boot with a `mkfs.fat` image before it can close.
